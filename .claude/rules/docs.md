# 文書の運用

> [!IMPORTANT]
> 文書には**今の状態だけ**を書く。経緯は git の履歴に任せる。

| 決まり | 中身 |
| --- | --- |
| 書き換える | 事実が変わったら、その箇所を書き換える。末尾への追記や「以前は〜」で済ませない |
| 1 つの事実は 1 か所 | どこに書くかは下の「文書ごとの中身」で決める。ほかの文書はリンクで指す。例外は README のバッジだけ（CLAUDE.md の表で一緒に直す） |
| 書く前に探す | 事実を書く前に、同じ語を grep で探す。見つかったら書き足さず、そこへリンクする |
| 消す | 使わなくなった節・表の行・図は消す。空の見出しを残さない |
| 決まっていないこと | 「未決」と書く。決まったら書き換えて「未決」を消す |
| 確かめていないこと | `[!WARNING]` にまとめる。確かめたら本文に結果を書き、WARNING から消す |

## 文書ごとの中身

| 文書 | 書く | 書かない |
| --- | --- | --- |
| README | 入口、準備、コマンド、バッジ | 機能の中身、決定 |
| CLAUDE.md | 作業と文書の対応、AI への決まり | 文書の書き方（このファイル） |
| overview | 何を作るか、守ること、未決 | 作り方 |
| architecture | 今の形（フォルダ、ターゲット、依存、署名の状態） | 理由、選ばなかった案、decisions の決定の言い直し |
| decisions | 決定、理由、選ばなかった案 | 形の詳しい説明（architecture へリンク） |
| data | 表の形と、その決まり | なぜその形か |
| roadmap | 作る順番、状態、画面 | 設定・環境の状態 |
| spec/export-format | 書き出しの形式 | 表の形（data へリンク） |

## 表現の使い分け

| 表現 | 使う場面 | 使わない場面 |
| --- | --- | --- |
| 表 | 項目が 3 つ以上並ぶもの、比較 | 1〜2 項目なら文で書く。列が 1 つなら箇条書きにする |
| Mermaid の図 | 依存の向き、処理の流れ、表どうしの関係 | 表で足りるもの |
| フォルダの木 | フォルダ構成 | |
| アラート | `NOTE` 補足、`IMPORTANT` 守ること、`WARNING` 未検証・注意 | 本文の言い換え。1 節に 1 つまで |
| バッジ | README の、変わりにくい事実（対応 OS・言語の版） | 進み具合など、よく変わるもの |
| 状態の絵文字 | roadmap の状態（✅ 完了、🚧 作業中、⬜ 未着手） | ほかの文書 |
| グラフ | 数値のデータがあるとき | 数値がないとき |
| 画像 | 使わない。AI が読めず、差分も見えない | |
