# 筋書きの一覧

> [!NOTE]
> 画面のモデルのテストを、iOS と Android で 1 件ずつ結び付けた一覧の読み方が分かる。
> 一覧は [scenarios/models.tsv](scenarios/models.tsv) にあり、テストを足した時の手順もここにある。
> Core の計算をそろえる fixtures は、[fixtures](fixtures.md) にある。

## 🎯 目的

iOS の動きを正とし、Android のモデルの動きとの違いを一覧に出す。筋書きは、テストの関数 1 つが確かめる 1 つの動きである。

| 対象 | 場所 |
| --- | --- |
| iOS のテスト | `ios/Packages/KakeibotApp/Tests/FeaturesTests/` の `@Test` の関数 |
| Android のテスト | `android/featuremodels/src/test/` の `@Test` の関数 |

## 📏 一覧の形

一覧は、タブ区切りの文字のファイルである。1 行目は見出しで、2 行目から 1 行が 1 つの筋書きになる。

| 列 | 中身 |
| --- | --- |
| `id` | 筋書きの ID。付け方は下の「ID の付け方」にある |
| `ios` | iOS のテスト。`<スイート>/<関数>` の形で 1 つだけ書く |
| `android` | Android のテスト。`<クラス>/<関数>` の形で書き、複数ある時は半角の空白で区切る |
| `status` | 区分。下の「区分」の表の語を書く |
| `note` | 違いの中身か、Android のテストが無い理由。60 字までの 1 文で書く |

行の並びは、iOS のスイートごとにまとめ、スイートの中は iOS のファイルの順にする。

| 場面 | 書き方 |
| --- | --- |
| iOS の 1 つのテストを、Android が複数に分けている | `android` に並べて書く |
| Android の 1 つのテストが、iOS の複数のテストを確かめる | それぞれの行の `android` に、同じテストを書く |
| スイートの相手が、Android に丸ごと無い | 1 行にまとめる。`id` を `<モデル>.*`、`ios` を `<スイート>/*` にする |
| Android のテストの関数の名前 | 空白を入れない。バッククォートの名前は、一覧に書けない |

## 🏷️ ID の付け方

ID は `<モデル>.<筋書き>` の形で、小文字の英数字とハイフンで書く。

| 部分 | 付け方 | 例 |
| --- | --- | --- |
| モデル | iOS のスイートの名前から `Tests` と `Model` を落とし、語をハイフンでつなぐ | `EntryModelTransferTests` は `entry-transfer` |
| 筋書き | iOS の関数の名前の語を、ハイフンでつなぐ | `savesNewEntry` は `saves-new-entry` |
| Android だけの行 | Android のクラスと関数の名前から、同じ決まりで付ける | `ScreenObservationTest` は `screen-observation` |

テストの関数の名前を変えても、筋書きが同じなら ID は変えない。モデルの部分は、検査がテストの型の名前と比べる。

## 🗄️ 区分

区分は、Android の側の状態で決める。

| 区分 | 意味 | `android` の列 |
| --- | --- | --- |
| `対応` | 同じ筋書きのテストが両方にある | 書く |
| `違い` | Android の動きが iOS と違うと、コードを読んで確かめた。直す候補である | テストが違う動きを確かめている時だけ書く |
| `未確認` | Android に機能はあるが、テストが無い。動きが同じかは確かめていない | 空 |
| `未移植` | Android のモデルと画面に、その機能が無い | 空 |
| `iOSのみ` | OS の仕組みの違いで、Android に要らない | 空 |
| `Androidのみ` | Android だけにあるテスト。`ios` は空にする | 書く |

`未確認` は、推測で `未移植` にしない。Android のモデルと画面を読み、機能が無いと確かめてから `未移植` にする。

直す候補は、`違い` の行である。`未確認` は、テストを写して動きを確かめる候補である。確かめた結果で、`対応` か `違い` に変える。

## 🪜 テストを足した時

テストを足す・消す・名前を変える時は、同じ commit で一覧を直す。

| 変更 | 一覧の直し方 |
| --- | --- |
| iOS にテストを足した | 行を足す。Android のモデルを読み、区分を決める |
| Android にテストを足した | 対応する iOS の行の `android` に書き、区分を `対応` にする。iOS に相手が無ければ `Androidのみ` の行を足す |
| Android の違いを直した | テストを足して、区分を `対応` にする。`note` は消す |
| テストの名前を変えた | 行の `ios` か `android` を直す。ID は変えない |
| テストを消した | 行を消す。相手のテストが残る時は、区分を決め直す |
| Android に画面を移した | スイートごとの行を消し、テストを 1 件ずつの行に分ける |

## 🧪 確かめること

`make verify-docs` が `scripts/scenarios-check.py` を走らせる。確かめることは、次のとおりである。

- iOS のテストの関数が、すべて一覧の 1 行かスイートごとの行に載っている。
- Android のテストの関数が、すべて一覧のどれかの行に書かれている。
- 一覧に書いたテストが、実際にある。
- ID が重ならず、区分と列の組み合わせが上の表のとおりである。

区分ごとの件数と `違い` の一覧は、`make scenarios` で出す。ほかの区分の行は、次のコマンドで出す。

```sh
scripts/scenarios-check.py --list 未確認
```

## ⚠️ テストの無い違い

iOS にもテストが無く、一覧の行にできない違いは、ここに残す。直した時と、iOS にテストを足して行にした時に、項目を消す。

> [!WARNING]
> どれもコードを読んで見つけた物で、動かして確かめてはいない。

- 入力: 変更があっても、確かめずに閉じる。iOS は `isChanged` の時に確かめる。
- 入力: 口座に合わないカテゴリを、読み込みの時に付け替えない。
- 入力: 請求の選択肢が無い時も、請求月をそのまま保存する。iOS は落とす。
- 記録: 表示の保存の失敗を捨てる。iOS は「保存できませんでした」を出す。
- 記録: 月の始まりの日を変えても、表示の月を今の期間に戻さない。
- 記録・振り返り: 設定を読む前の週の始まりが月曜である。iOS は日曜である。
- 振り返り: 一覧に無いカテゴリを「未分類」で出す。iOS は落とす。
- タブ: 読み込みの失敗の後に、やり直しのボタンが無い。iOS は `isListFailed` で出す。
- 知らせ: 次の処理が成功すると、前の知らせが消える。iOS は消さない。
- 設定: 予算と固定費の一覧は、共有の記録の読み込みの失敗を受けていない。
- 保存の失敗: 表示と選択の保存で、容量が足りない時の専用の文が無い。
