# 保存

> [!NOTE]
> DB・マイグレーション・書き出し・バックアップの決定と、その理由が分かる。
> 表の形は [data](../data.md) にある。

## DB

**決定：GRDB の DatabasePool を App Group に置く。**

| 項目 | 内容 |
| :---: | --- |
| 💡 理由 | SQL で集計と移行を書ける。ウィジェットからも読める |

## マイグレーションの値

**決定：マイグレーションの中の値は直書きで固定し、enum に値を足す時は表を作り直すマイグレーションとセットにする。**

| 項目 | 内容 |
| :---: | --- |
| 💡 理由 | 今の enum から作ると、公開後に case を足した時に CHECK が食い違う。新しく入れた端末と、古い版から上げた端末で違う |
| ❌ 却下 | ~~マイグレーションで enum の `allCases` を使う~~ case を足すと CHECK が食い違う |

> [!IMPORTANT]
> 固定した値が今の `allCases` と一致するかは、`MigrationFrozenValuesTests` が確かめる。case を足すと落ちる。

## マイグレーションから呼ぶコード

**決定：マイグレーションは、Core の型と計算を呼ばない。複数の番号で使う SQL は、`MigrationSyncTriggers` のような固定の型に置く。**

| 項目 | 内容 |
| :---: | --- |
| 💡 理由 | Core の計算を変えると、配った後のマイグレーションの結果まで変わる |
| 例外 | `MigrationV025` は `Recurring` の予定日の計算を呼ぶ。配った後なので変えない |

## DB の変更を画面に届ける

**決定：`ValueObservation`。**

| 項目 | 内容 |
| :---: | --- |
| 💡 理由 | 依存を増やさない |
| ❌ 却下 | ~~GRDBQuery~~ 依存が増える |
| ❌ 却下 | ~~SQLiteData~~ 依存が増える |

## 書き出しの形式

**決定：Core に置く。**

| 項目 | 内容 |
| :---: | --- |
| 💡 理由 | DB なしで往復を試せる。Android に移せる |
| ❌ 却下 | ~~Store に置く~~ DB なしで往復を試せない |

## バックアップ

**決定：設定の「データ」の「バックアップ」から、全データを JSON のファイルに書き出す。**

| 項目 | 内容 |
| :---: | --- |
| 💡 理由 | 無料で、サーバーを使わずに、機種変更でも自分でデータを戻せる |
| ❌ 却下 | ~~iCloud の同期だけに任せる~~ 同期は Pro なので、無料で戻せない |
| 関連 | 形式の決まりは [export-format](../../spec/export-format.md) にある |

> [!IMPORTANT]
> - ファイルの名前は `kakeibot-年-月-日.json` にし、保存先は使う人がファイルの画面で選ぶ。
> - 読み込む時は、書き出した日と記録・口座（`Wallet`）の数を出して確かめてから、全部置き換える。
> - 置き換えと同じ書き込みの中で、いまのデータを JSON にして保存する。

### 退避の世代

- 退避の保存先は Application Support で、2 世代まで持つ。
- 新しい保存を 1 つ目に置けてから、前の 1 つ目を 2 つ目へ送り、前の 2 つ目は消す。
- 途中で失敗したら、前の 2 つの世代を元に戻し、読み込まずにエラーを出す。
- 退避は MainActor の外で読んで解く。読めない退避は行に出さず、行と読み込みは同じファイルで引く。

### バックアップの画面

- 画面は、書き出しの「残す」と、読み込みと退避の「戻す」の節に分ける。同期か共有を使っている間は、「戻す」の行を押せなくし、理由を節の下に出す。
- 保存したデータごとに、「戻す」の節に「日時 の退避に戻す」を出す。確認を通して、全部置き換える。
- 同じ画面から、記録を表計算用の CSV（`kakeibot-年-月-日.csv`）にも書き出せる。
- CSV は全部置き換える読み込みには使わない。CSV から記録を足すのは、下の「今の家計簿からの乗り換え」にある。

## 今の家計簿からの乗り換え

**決定：設定の「データ」から、ほかの家計簿や表計算の CSV を読み、今のデータに記録を足す。無料で使える。**

| 項目 | 内容 |
| :---: | --- |
| 💡 理由 | 列をどう読むかを人が選ぶので、どのアプリの CSV でも読める |
| 💡 理由 | 乗り換えの壁を下げるので、無料にする。乗り換える前の人は、Pro の値打ちをまだ知らない |
| 💡 理由 | 足すだけなので、読み込んだ後も今の記録が残る。同じファイルを 2 回読んでも記録が重ならない |
| ❌ 却下 | ~~アプリごとに決まった列の形だけを読む~~ 相手が形を変えると読めなくなる |
| ❌ 却下 | ~~Pro に含める~~ 乗り換える前の人は、Pro の値打ちをまだ知らない |
| ❌ 却下 | ~~JSON のバックアップと同じく全部置き換える~~ 読み込んだ後に今の記録が残らない |
| 関連 | 読める形は [export-format の CSV の読み込み](../../spec/export-format.md#-csv-の読み込み)にある |

> [!IMPORTANT]
> - 選んだファイルの 1 行目を列の名前として出し、日付・金額・種類・カテゴリ・財布（`Wallet`）・メモの列を人が選ぶ。日付と金額は必ず選ぶ。
> - 次に、ファイルのカテゴリと財布の名前を、今のものに対応させる。対応の無い名前は、新しく作る。
> - 読み込む前に、先頭の数件と、足す件数・飛ばす件数・期間を出して確かめる。
> - 今の記録と日付・種類・金額・メモがそろう行は、重なりとして飛ばす。ファイルの中で同じ行が続く時は、どれも足す。
> - 新しく作る財布の最初の残高は 0 にする。読み込んだ後に、残高の調整（`Adjustment`）で今の額に合わせる案内を出す。
