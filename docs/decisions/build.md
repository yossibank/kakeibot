# 作り方

> [!NOTE]
> リポジトリ、署名、整形、テスト、画面の言語と言葉づかいの決定が分かる。

## 共通化

**決定：Swift で先に作り、fixtures で Kotlin 版とそろえる。**

| 項目 | 内容 |
| --- | --- |
| 理由 | Swift が得意で iPhone を毎日使い、AI の段階は Swift 専用である。iOS をストアに出してから、13 番で Android に取りかかる |
| 却下 | Kotlin Multiplatform、Compose Multiplatform、Flutter、Swift SDK for Android |

## リポジトリ

**決定：1 つにまとめる。**

| 項目 | 内容 |
| --- | --- |
| 理由 | fixtures と書き出しの形式を両 OS で共有する |
| 却下 | OS ごとに分ける |

## 対応端末

**決定：iPhone のみ。**

| 項目 | 内容 |
| --- | --- |
| 理由 | iPad 向けの画面の配置とスクリーンショットが要らない。あとから足せる |
| 却下 | iPhone と iPad |

## 署名

**決定：自動。**

| 項目 | 内容 |
| --- | --- |
| 理由 | 1 人・端末 1 台・CI なしなので、端末の追加・更新・提出を Xcode に任せられる |
| 却下 | 手動 |

## プロジェクトのファイル

**決定：`.xcodeproj` をそのまま管理する。**

| 項目 | 内容 |
| --- | --- |
| 理由 | 1 人なので衝突しない。中身はほぼパッケージ側 |
| 却下 | XcodeGen、Tuist |

## ワークスペース

**決定：プロジェクトと 2 つのパッケージを、`.xcworkspace` で並べる。**

| 項目 | 内容 |
| --- | --- |
| 理由 | ナビゲーターでプロジェクトとパッケージが同じ高さに並び、見分けやすい |
| 却下 | パッケージのフォルダをプロジェクトの中に入れる |

## 整形

**決定：SwiftFormat（Mint で版を固定）。**

| 項目 | 内容 |
| --- | --- |
| 理由 | 自分で整形を走らせずに済む。一部だけステージしたファイルは、pre-commit が整形を取り消すので壊れない |
| 却下 | hook は違反を止めるだけで直さない、hook がステージし直して commit まで通す |
| 却下 | SwiftLint も入れる |

決まり：

- commit の前に pre-commit が整形し、直したら commit を止める。
- ステージし直すのは人。

## 文書の確認

**決定：文書の書き方の決まりは、Claude Code のフックで確かめる。**

| 項目 | 内容 |
| --- | --- |
| 理由 | 文書を書くのはほぼ Claude なので、書いたその場で直せる。リポジトリごとの準備が要らない |
| 却下 | pre-commit で確かめる、自動では確かめない |
| 関連 | フックは claude-config の `hooks/docs-check.py` |

## テストの走らせ方

**決定：CI は置かない。**

| 項目 | 内容 |
| --- | --- |
| 理由 | リポジトリは非公開で、GitHub Actions を使わない |
| 理由 | 結果の変わらない変更で待たず、同じビルドを 2 回せず、長いログから失敗を探さずに済む |
| 却下 | GitHub Actions で走らせる、手元の Mac を GitHub Actions のランナーにする |
| 却下 | push のたびに走らせる、`make test-build` も別に走らせる、xcodebuild の出力をそのまま出す |
| 却下 | 先にシミュレーターを起動する。起動の途中は `simctl list` と `xcodebuild` が待たされ、かえって遅い |

決まり：

- PR を作る前に、Claude が手元で `make test` を 1 回走らせ、結果を PR の本文に書く。
- push し直すときは、Swift か fixtures を変えたときだけ走らせ直す。
- 文書だけの PR では走らせない。
- ビルドは別に走らせず、`make test` のビルドで兼ねる。
- ビルドとテストの出力は xcbeautify で整える。

## 画面の言語

**決定：文字は日本語で書き、iOS の開発言語を `ja` にする。**

| 項目 | 内容 |
| --- | --- |
| 理由 | 日本語で使う人に向けたアプリで、日付選択などの OS の部品も日本語で出る |
| 却下 | 英語で書いて日本語に訳す |

決まり：

- ほかの言語は、出すときに訳を足す。

## 画面の言葉づかい

**決定：説明と知らせは「記録しました」「動かせます」のように、柔らかい丁寧な言い方で書く。**

| 項目 | 内容 |
| --- | --- |
| 理由 | 使ってもらうアプリなので、言い切りより柔らかく聞こえる |
| 却下 | 「記録した」のような言い切り |

決まり：

- ボタンは「取り消す」「削除」のように短く書く。
